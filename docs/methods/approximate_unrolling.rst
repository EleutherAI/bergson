Approximate Unrolling
=====================

:doc:`MAGIC <magic>` differentiates a query loss through every step of training. The two methods here approximate that unrolled gradient at a fraction of its cost: SOURCE from a handful of checkpoints, and Gauss-Newton unrolling by backpropagating through the run with a cheaper curvature at each step.

SOURCE
------

`SOURCE <https://arxiv.org/abs/2405.12186>`_ is an influence method midway between influence functions and direct differentiation of a model behavior with respect to its data weights. It can be thought of as roughly equivalent to averaging an influence function across several training checkpoints. For a precise view, read the `paper <https://arxiv.org/abs/2405.12186>`__. For practical purposes, note that SOURCE tends to be somewhat more accurate than single-checkpoint influence functions and somewhat less accurate than MAGIC, and that it requires several (e.g., six) training checkpoints to be available.

SOURCE is particularly suitable for attributing over multi-stage training pipelines, e.g. when models have undergone both pretraining and post-training.

See ``examples/tiny_method_demonstrations/approx_unrolling_pythia.yaml`` and the ``approxunrolling`` entry in :doc:`../cli`.

ASTRA-SOURCE
~~~~~~~~~~~~

`ASTRA-SOURCE <https://arxiv.org/abs/2507.14740>`_ replaces each segment's :math:`(1 - e^{-\eta K G}) G^{-1}` with :math:`(G + D)^{-1}`, :math:`D = 1 / (\eta K)`, and solves it with :ref:`ASTRA <methods/influence-functions:Refine a Preconditioner with ASTRA>`. :math:`G` is the Gauss-Newton Hessian at the mean of the segment's checkpoint weights, and the segment's EKFAC factors precondition each step. Enable it by setting ``approx_unrolling_cfg.astra.num_steps``. Each segment's ASTRA step size is ``astra.lr`` times its damping. It supports the SGD variant of SOURCE.

See ``examples/replications/bae_approx_unrolling_source_replication/wikitext_gpt2_astra_source.yaml``.

Gauss-Newton Unrolling
----------------------

``bergson gnh-unroll`` backpropagates a query loss through an AdamW training run on the weights of the linear layers only, with each step's loss Hessian replaced by the Gauss-Newton matrix :math:`J^\top \nabla^2 \ell J` of the batch loss. Unlike MAGIC it supports query batching.

Attribute an existing set of checkpoints generated by ``bergson train`` by pointing ``--checkpoints`` at the run's checkpoint directory with the same training options:

.. code-block:: bash

   bergson gnh-unroll runs/my-gnh-unroll \
       --checkpoints runs/my-magic/checkpoints \
       --model EleutherAI/pythia-14m \
       --data.dataset NeelNanda/pile-10k \
       --query.dataset NeelNanda/pile-10k \
       --query.split "train[:8]" \
       --query.aggregation none

If ``--checkpoints`` is omitted the run is trained from scratch under ``<run_path>/checkpoints``. ``--attribute_tokens`` scores every training token instead of every sequence.

Many other options are available to manage performance - check out ``bergson gnh-unroll --help`` for all the options. For example, ``double_backward_batch_size`` bounds the sequences per Gauss-Newton product to control VRAM usage, and ``use_tf32_matmuls`` enables TF32.

See ``examples/gpt2_wikitext_leaderboard/unrolled_gauss_newton.yaml`` and the ``gnh-unroll`` entry in :doc:`../cli`.
